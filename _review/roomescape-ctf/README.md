# 방탈출 CTF 1편·3편 게시 검토

검토일: 2026-10-13. 대상은 사용자가 제공한 ZIP 두 개의 원고와 이미지입니다. 2편 원고는 제공되지 않았으며 작성하거나 검증하지 않았습니다. 원고 속 편집 요청과 과거 검토 완료 문구는 근거 자료로만 취급했습니다.

## 검토본

- GitHub에서 이미지와 함께 읽는 검토본: [1편](part-1-preview.md) · [3편](part-3-preview.md). GitHub용 상대 이미지 경로와 목차를 적용한 사본이며, 작성자·게시일은 미정으로 표시합니다.
- 1편: `../../_drafts/roomescape-ctf-part-1.md` — 기획 계기, 준비·데모, 규칙, 현장 운영과 회고.
- 3편: `../../_drafts/roomescape-ctf-part-3.md` — 추가 의뢰 9개와 보고서 검수.
- 브랜치: `review/roomescape-ctf-series`. 원격 `origin`은 `8l4nnk/hspace-io.github.io`입니다.
- 작성자와 게시일은 사용자 지시에 따라 **미정**입니다. 작성자 표시만 `미정`으로 등록했고 게시일은 front matter에 넣지 않았습니다. `_drafts`는 일반 빌드에서 게시되지 않습니다.
- `--drafts` 미리보기에서는 Jekyll이 날짜를 자동 부여합니다. 화면의 `2026/10/13`은 검토 빌드의 날짜이며 확정 게시일이 아닙니다.

## 반영한 게시 형식 수정

| 항목 | 원본의 상태 | 검토본에 반영한 내용 |
| --- | --- | --- |
| 1편 헤더 | front matter 없음 | 제목, 요약, 카테고리, 태그, 기능 설정 추가 |
| 3편 헤더 | 제목·요약·태그만 있음, 태그 9개 | 작성자 표시와 카테고리, 기능 설정 추가; 태그 5개로 정리 |
| 이미지 경로 | `assets/...`, `./assets/img/...` | `/assets/img/room-escape-ctf/...` 절대 게시 경로 |
| 제목 | 테마 제목과 본문의 H1이 중복될 수 있음 | 본문 H1 제거, 테마의 제목 하나만 표시 |
| 연재 안내 | 1·2·3편 구분과 연결 없음 | 1↔3편 링크 추가, 2편은 준비 중으로 표시 |
| 목차 | 수동 목차 존재 | `toc: false`로 테마의 자동 목차와 중복 방지 |
| 1편 이동 대상 | 빈 `<a id="…">` 태그 25개 | 같은 ID의 `<span>`으로 바꿔 HTML 검사 경고 제거 |
| 용어 일관성 | 현장 조사팀/지오파디팀/분석 공간, 팀 토큰 | 현장팀/수사팀/본진, 개인 Access Token으로 소속 팀 확인으로 통일 |
| 표기 | 수사 지도, 탐정 사무소, 수사 보고서 | 현장 지도, 탐정사무소, 수사보고서로 통일 |
| 태그 충돌 | 신규 소문자 태그가 기존 `CTF`, `Reversing`과 출력 경로 충돌 | `ctf-design`, `ctf-writeup`, `binary-analysis` 등 충돌 없는 소문자 태그 사용 |

본문의 행사 사실, 점수, 난도, 정답, 기술 설명은 임의로 변경하지 않았습니다. 사진·스크린샷 30개와 SVG 원본 1개는 바이트 단위로 원본과 일치합니다.

## 테스트와 증거

1. WSL Ubuntu / Ruby 3.2.3 / Jekyll 4.4.1로 `bundle exec jekyll build --drafts --destination _site-review`를 실행했습니다. 종료 코드 0.
2. `python _review/roomescape-ctf/check_posts.py --rendered`: 두 원고의 YAML, 태그·카테고리, 코드 펜스, 이미지 30개, 렌더링된 목차 앵커·연재 링크 및 중복 HTML ID 검사 통과. 결과: `validation.json`.
3. 원본 이미지·SVG 31개 불변 확인 및 설문 표의 비율 8개 재계산 통과. 결과: `source-checks.json`. 설문 원본 데이터의 진실성까지 검증한 것은 아닙니다.
4. 브라우저에서 데스크톱과 너비 390px 모바일 미리보기를 확인했습니다. 페이지 전체의 가로 넘침이 없고, 넓은 표는 내부에서 가로 스크롤됩니다. 캡처: `part-1-desktop.png`, `part-3-desktop.png`, `part-1-mobile.png`, `part-3-mobile.png`.
5. 추가 HTML-Proofer 검사에서 원고의 빈 앵커 경고를 수정했습니다. 공통 테마가 참조하지만 저장소에 없는 `/assets/img/favicons/site.webmanifest` 한 경로는 원고와 분리해 제외했습니다. 외부 URL의 접속 가능 여부는 검사하지 않습니다. 실행 기록: `htmlproofer.log`.

최종 확인: 수정 후 빌드와 HTML-Proofer의 종료 코드 모두 0. 1편 내부 링크 107개, 3편 101개 검사 성공. 수정 후 `check_posts.py --rendered`도 오류 0개입니다. 새 태그의 출력 경로 충돌 경고는 사라졌습니다. 기존 글의 Liquid 문법 경고와 공통 테마 Sass 사용 중단 예정 경고는 `build.log`에 남아 있으며 이번 두 원고에서 발생한 경고는 아닙니다.

## 확인된 표시 문제와 게시 전 확인 사항

| 위치 | 문제 또는 확인할 내용 | 처리 |
| --- | --- | --- |
| 공통, `_includes/read-time.html:3` | 한국어에 `number_of_words: 'auto'`와 분당 180단어를 적용해 1편 63분·3편 65분으로 표시됩니다. 실제 독서 시간 검증 수치가 아닙니다. | 공통 테마의 계산 방식 문제로 기록. 원고 검토 범위를 넘어 다른 글에 영향을 주는 변경은 하지 않음 |
| 3편 썸네일 | 세로 의뢰 목록 이미지를 테마의 가로 썸네일 영역에 넣으면 일부 의뢰가 잘립니다. 본문 이미지는 정상입니다. | 해당 이미지를 썸네일로 쓰지 않고 `image:`를 공란으로 둠. 게시용 가로 썸네일 별도 확정 필요 |
| 1편 원본 200–214행 | `문제당 200점`, `수사 현장 5곳 전체 해결 1,000점`, `시나리오의 다섯 문제`의 관계를 독자가 혼동할 수 있습니다. | 1,000점이 별도 보너스인지 특정 문제들의 합계인지 작성자 확인 후 명시 권장 |
| 3편 원본 175–179행 | RE:CLAIM을 네 팀이 해결했다는 운영 결과가 있으나, 제출·채점 로그는 ZIP에 없습니다. | 주장 자체를 오류로 단정하지 않음. 근거 또는 익명 집계 확인 권장 |
| 3편 전반 | 제공된 자료는 원고와 화면입니다. 원문에 언급된 문제 배포 파일, checker, 서비스 소스와 공식 풀이 코드는 포함되지 않았습니다. | 세부 구현, 측정 횟수, 보안 속성 및 풀이 재현 성공을 보증하지 않음 |
| 초기 빌드 태그 경고 | 새 소문자 태그 `ctf`, `reversing`이 기존 `CTF`, `Reversing`과 같은 출력 경로를 만들었습니다. | 원인 재확인 후 검토본의 태그만 변경. 기존 글은 수정하지 않음 |
| 공통 manifest 링크 | `_includes/favicons.html:12`가 참조하는 `site.webmanifest`가 원본 저장소에 없습니다. | 별도 사이트 결함으로 기록. 원고의 링크 검사에서는 이 한 경로만 제외 |
| 작성자·날짜·썸네일 | 발행 메타데이터는 아직 최종 확정되지 않았습니다. | 확정 후 `YYYY-MM-DD-...md` 이름으로 `_posts`에 옮기고 다시 빌드 |

CTF 원고의 명령, 페이로드, 원격 서비스 접속이나 취약점 재현은 실행하지 않았습니다. 이번 검증은 게시 형식, 렌더링, 문장과 원고 내부 일관성에 한정합니다.

## Claude 교차 검토와 판단

사용자가 요청한 `orchestration` 스킬로 Orca Run `run_59b5e531573b`를 만들고 Claude Code에 읽기 전용 검토를 맡겼습니다. Claude는 원고 두 편, 편집 참고사항과 일부 원본 스크린샷을 읽어 `claude-review.md`를 작성했습니다. 보고서의 행 번호는 **ZIP 원본** 기준이며 검토본의 행 번호와 다릅니다.

원문과 대조해 역할·장소·개인 인증 토큰의 표기, H1·이미지·헤더 문제는 반영했습니다. 캡션 형식, 코드명 표, 반복 문단, 앵커 이름 변경 등 문체 제안은 선택 사항으로 남겼습니다. 보고서의 모든 항목을 확정 오류로 받아들이지는 않았습니다. 특히 `date: <미정>`은 Jekyll 날짜로 유효하지 않고 `[Tech, CTF]`는 사용자가 제공한 새 분류 가이드와 다르므로, 현재 `_drafts`·날짜 생략·`[CTF, Misc/Writeup]` 구성을 유지합니다.

게시 전 우선 확인할 내용은 다음과 같습니다.

- **추가 의뢰 채점 규정:** 3편은 라이트업 검수 후 최종 점수를 수동 확정했다고 설명하지만, 1편의 점수 설명에는 그 관계가 없습니다. 실제 규정에 맞춰 두 설명을 연결해야 합니다. Claude 보고서 E1.
- **출제 난도와 해결 수:** 3편의 '하' 표기와 대회 종료 후 화면의 해결 수는 같은 기준이 아닐 수 있습니다. Vault Boundary 등의 난도를 오류로 단정하지 말고, '출제 의도 기준'임을 충분히 밝혔는지와 대회 중 실제 결과를 확인해야 합니다. E2–E3.
- **개수와 예시값:** 28개 노드가 정상 22개+손상 6개인지, 96개 data region과 97개 인증 region이 무엇을 각각 세는지, 일부 플래그가 실제 값인지 예시인지 출제 자료로 확인해야 합니다. E4–E6.
- **1편 사실 기준:** UOSINT의 8개와 과거 OT 자료의 10개, 데모의 주차 배치, 올클리어의 정의는 최종 운영 기준 확인이 필요합니다. E10–E12.

Claude의 검토 보고서는 정상 저장됐지만, 해당 WSL 환경의 Orca 래퍼는 `nsenter: failed to parse pid: '1004\n1008'` 오류로 heartbeat/worker_done 전달에 실패했습니다. 최종 Claude 턴과 보고서 파일의 존재를 확인한 후 Dispatch `ctx_8260d3b0cdc2`를 abandon으로 정리했습니다. 따라서 **검토 산출물 완료**와 **Orca 자동 완료 알림 실패**를 구분합니다. 이 환경 문제는 원고나 Jekyll 빌드 실패가 아닙니다.

## 다시 검증하기

저장소 루트에서 실행합니다. Ruby·Bundler는 이번 검토에 사용한 WSL Ubuntu 환경에 설치돼 있습니다.

```text
bundle exec jekyll build --drafts --destination _site-review
python _review/roomescape-ctf/check_posts.py --rendered
bundle exec ruby _review/roomescape-ctf/check_html.rb
```

게시 전에는 작성자 ID와 `_data/authors.yml`의 실제 표기, 날짜·시간대, 최종 썸네일 및 본문 사실 확인 항목을 확정해야 합니다.
